## Findings that shaped the script

- `herdr pane split` prints JSON (`result.pane.pane_id`), has no name flag, and
  `herdr pane run <pane> <command>` types the command into the pane's login shell.
  The pane therefore does not inherit the dispatcher's environment; the runner
  script exports `PATH` and the launch variables itself.
- `codex exec resume` has no `--sandbox` flag, so the sandbox is set with
  `-c sandbox_mode="workspace-write"` on both first and resumed runs. A worktree's
  git directory lives in the main checkout's `.git`, outside the Codex workspace,
  so it is added to `sandbox_workspace_write.writable_roots`.
- `opencode mcp list`: no MCP servers configured, so OpenCode needs no Context7
  switch (`launch.opencode.mcp_none`).
- Claude `--allowedTools` and `--disallowedTools` are variadic; the prompt goes on
  stdin so no flag swallows it.
- The system bash is 3.2 (no `mapfile`), so the logic is Ruby 2.6, like the hooks.
- A lone script path with a space is split by Ruby's single-string spawn; preflight
  scripts run through `bash <path>`.
- YAML 1.1 reads `caveman: off` as `false`. The first reviewer dry run showed
  "caveman on" for the Opus reviewer; fixed.
