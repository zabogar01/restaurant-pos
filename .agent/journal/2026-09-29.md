## KIT-002a

The owner pasted a follow-up to KIT-002: Context7 for the librarian only, `ask.sh`

What shaped it:

- **The premise was off.** The owner thought `ask.sh librarian` had web search only. In
  fact `~/.codex/config.toml` enables Context7 for every Codex run. The lead offered to
  disable it globally; the owner said to leave the global file as it is. Everything was
  therefore done per run.
- **Codex has a second route.** The recorded librarian run called Context7 through the
  ChatGPT "Context7" app (`codex_apps`), not the config server. Turning off the config
  server alone left the app available. The off switch needs both flags.
- **Model self-reports are unreliable.** Haiku, asked to list its tools, named tools it
  could not call (from the deferred-tools list). The `claude -p` stream-json init event
  was used instead, and each CLI's own listing command for skills (`codex debug
  prompt-input`, `opencode debug skill`).
- **Every CLI can gate skills per run**, with limits: Claude cannot hide one plugin skill
  (only the whole plugin); Codex gates by path; OpenCode has a real allowlist. The lead
  built `skills-report.sh --gate` and proved it end to end on all three.
- The lead proposed changing the architect's assigned `grill-me` to `grilling`, because
  `grill-me` is a user-invoked wrapper. The owner read it as renaming a skill and declined;
  the lead clarified that no folder would change. With no gate, nothing breaks.

Owner rulings, all in DECISIONS.md: Context7 for the librarian only; the global Codex
config stays; KIT-003 accepted; `grill-me` stays; `skills:` stays a hint and KIT-004
does not gate skills. The owner merged the branch as PR #16 (`3adb054`).
