## Caveman off, per run

Claude Code loads caveman as a user-level plugin (`caveman@caveman`). Its
SessionStart hook injects "CAVEMAN MODE ACTIVE" into every `claude -p`.

**Rejected: `CAVEMAN_DEFAULT_MODE=off`.** In off mode the plugin's
`caveman-activate.js` runs `fs.unlinkSync(flagPath)` on
`~/.claude/.caveman-active`, a file shared by every Claude session on the
machine. The mode tracker reads it on each prompt. A worker launched this way
would switch caveman off for the lead as well.

**Chosen: `--settings '{"enabledPlugins":{"caveman@caveman":false}}'`**, which
disables the plugin for that process only.

Proof, `claude -p --model haiku`, run in a scratch directory:

| Run | Self-report (`CAVEMAN_IN_CONTEXT=`) | Caveman hook events (`--include-hook-events`, stream-json) | `~/.claude/.caveman-active` after |
|---|---|---|---|
| Plugin enabled (default) | `YES` | 2 | `full` |
| Per-run `--settings` override | `NO` | 0 | `full` (unchanged) |

The hook-event count is the mechanical proof. The self-report agrees with it.

Codex and OpenCode have no always-on caveman hook. Caveman exists there only
as an on-demand skill in `~/.agents/skills`, so their role prompts carry the
"full prose" rule.

## A wrong explorer suggestion, caught

For the P3 "`closeOrder` fires a quick sale with `type: 'table'`", the explorer
proposed passing the quick-sale type. `fireOrder` refuses `quick_sale`
outright (`fire.ts`: "a quick sale has no fire"). `closeOrder` borrows `'table'`
on purpose, so a quick sale's lines are fired at close. The suggested fix
would have made every quick-sale close refuse. The lesson is in
`roles/lead.md`: never copy an explorer's suggested fix without checking it.
