Purpose

Build and correct an order, fire it in rounds, discount it, void it. The screen the cashier spends the shift on. One screen, two variants: table and quick_sale.

Fixed by the PRD

  • A fire sends only lines not previously fired. There is no "reprint whole order to kitchen" control, ever. FR-E2, B-16
  • Removing a pending line takes no approval and is not audited. No confirmation dialog. FR-H2
  • Voiding a fired line needs a manager PIN and a reason, and emits one cancellation ticket covering only that work. FR-H4, AC-22
  • Refund never appears on this screen. Void is for open orders only. FR-H1, B-19
  • One discount per order. Preset: no prompt. Free-form: manager PIN. FR-F1, F2, F3, B-22
  • The gate covers the whole transition — replacing a free-form discount with a preset is still gated. FR-F8
  • Tax is derived and display-only, never added. B-4, FR-M4
  • Quantity is whole, maximum 99. FR-M5
  • Modifiers are flat — no nested groups. FR-C4
Ruling I-12 — one meaning per slot

An order line has three affordance signatures, readable in greyscale without reading the words:

  • Pending — a bordered square at the trailing edge. One tap and the line is gone: no prompt, nothing written. FR-H2, AC-3
  • Fired — that slot is empty. The row itself opens the void sheet, which demands a reason and a manager PIN and prints a cancellation ticket. FR-H4, B-16, AC-22
  • Voided — struck through and inert. Terminal.

The trailing slot is never re-used for a gated action. A control that is silent on one row and PIN-gated on the row above it teaches a reflex that is right most of the time, and paper cannot be un-printed. Absent, not disabled — the same reasoning as ruling C-1.

The group header carries the marker once per round rather than a tag on every row: the panel's first job is being read.

Ruling C-2

A quick sale has no fire control at all. Settling sends it. The settle button says so. FR-E5, G10

Ruling C-3

An 86'd item is disabled in place — the tile keeps its position, greys, and carries an 86 marker. It is never removed, because removal reflows the grid under a finger already moving. FR-C5, C6, AC-12

Within three seconds of the back-office toggle, no restart. Drawn here as a static state; the propagation is a two-second poll.

Ruling C-5

Same five actions disabled, two different causes, two different messages. The tab guard is the cashier's own doing and they can undo it. The lease is someone else's and they cannot. FR-G12, G13

I-12 under a lock — inert, not absent

Void is one of the five blocked actions, and FR-H1 defines void as applying to an open order or to lines on one. AC-3 calls removing an unfired line "voiding an unfired line". So the per-line remove control is a void too, and goes with the fired-line path. Every trailing slot here is empty.

That is I-12 holding, not a fourth signature. The slot means "removable now"; under a lock nothing is removable now, so the slot is empty on every row. The row body stops being a control for the same reason.

Why inert rather than absent. Ruling C-1 removes a control that is permanently impossible — a zero-total order can never be refunded, so a disabled Refund points at an override that does not exist. A settlement lock is temporary and each variant has a real route out: finish or cancel the payment, or wait for the other client. Naming that route points at something that exists.

Removing the rows would also be wrong on its own terms. FR-G13 says reads are never blocked, and these lines are what the cashier is still entitled to read. The rows are untouched; only the interaction goes, and the reason is named once per group header — never in the same words for the two locks C-5.

FR-G10 — the case this illustrates

This order holds a pending line while a payment is under way. Nothing prevents that: FR-G10 refuses the close, not the draft. The matching refusal is on POS-04 — follow "Back to payment".

FR-E4, B-17

Fire is refused while a pending line holds an 86'd item, and the offending line is named. Resolution is voiding the line or restoring the item. An unavailable item never reaches the kitchen.

FR-C7, AC-31

CATALOG_CHANGED. The command was built on stale catalog data and was rejected. No line was added at the stale price.

FR-A6, B-14, B-20

This is a modal over the screen that triggered it, never a route and never a mode. It authorises one action and does not persist.

A manager holding a back-office session still enters a PIN here. FR-A2c, AC-27

Cancelling writes an audit entry naming the actor with approver null. The cancel path is evidence, not a no-op. FR-J3, AC-18

Not visible in a still

  • Lines are grouped by fire round so the cashier can answer "did this go to the kitchen?" without asking. FR-E2 — grouping is the designer's call, see I-7.
  • Order state is server-held and survives a client or app restart. FR-D6
  • Snapshotted prices: later menu edits never change this order. FR-D4, B-8
  • Rejected commands leave the order exactly as it was. B-20
