Restaurant POS — wireframe prototype

Two clients, one server. Wireframe fidelity only: greyscale, system type, no brand, no colour, no imagery, no motion. Structure, hierarchy, density, affordance and flow. Visual direction is assigned downstream and anything invented here would be discarded.

All data is fake and hard-coded. Nothing calculates. Money figures follow the PRD worked example — subtotal 16.50, discount 1.65, tax included 1.35, service 0.74, total 15.59 — so the numbers are at least coherent with each other.

How to read this. Every screen is a real route. Every state below is a real, reachable variant of that route, reached with ?state=. Modals and sheets are overlays on their parent screen and never change the route — that distinction is load-bearing: manager approval is an overlay over whatever triggered it, never a page. Each screen carries an annotation rail on the right naming the requirements it satisfies and the behaviour a still picture cannot show.
Regular state Dashed = screen or behaviour ruled in from the "implied but unspecified" list
